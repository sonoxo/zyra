# 2. What a beginner can do now

## Mission Home is implemented

The authenticated dashboard now opens with a mission-first entry layer instead of forcing a beginner to understand the entire module catalog first.

The user can type an outcome into **“What do you want to accomplish?”**. A deterministic beginner router suggests an existing ZYRA surface. The router **does not execute tools, grant approvals, bypass US-CZ, or create external authorization**.

| Door | Beginner question | Starting surface | Readiness |
|---|---|---|---|
| 🛡️ **Protect Something** | “Is my project secure?” | scans / defensive security | 🟢 Strong |
| 👁️ **See With ZYRA** | “How does AI see my screen?” | ZYRA Eyes | 🟢 Strong demo hook |
| 🧠 **Investigate Something** | “What does this threat/source/CVE mean?” | threat intelligence / NXYZ evidence | 🟢 Strong |
| 🏗️ **Build Something** | “Where do I start building?” | repositories / integrations | 🟢 Beginner entry implemented |
| 🏛️ **Government / Contracting** | “How do I structure federal readiness?” | NXYZ ContractOps | 🟢 Advanced entry |
| 🚀 **Run an Operation** | “Where should this mission start?” | command center | 🟢 Beginner routing implemented |

The original advanced dashboard remains available below Mission Home, so the beginner-first change does not remove operational analytics.

# 9. Update protocol

Update this bulletin after a material feature change, capability-state change, onboarding/navigation change, major external collaboration change, policy-boundary change, significant failure/recovery, or priority-order change.

Every update must answer:

1. What changed?
2. What can a beginner do now?
3. What state changed: planned, implemented, CI verified, deployed, platform access, authorized action, third-party approved?
4. Did documentation change?
5. Did policy posture change?
6. What is the single highest-value next build?

Never upgrade a claim without evidence.

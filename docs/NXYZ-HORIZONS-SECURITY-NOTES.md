# NXYZ Horizons Handling Controls

This integration is designed for authorized investigative and due-diligence workflows using data the operator is permitted to process.

## Default controls

- Require authenticated NXYZ/Zyra access for gateway endpoints.
- Keep Horizons request/response payloads out of normal application response logging.
- Never commit private screening lists, investigation exports, session data, or credentials.
- Treat direct machine-to-machine Horizons access as unavailable until C4ADS provides an approved interface and the operator configures it.
- Do not scrape Horizons or automate account credentials.
- Treat name-only search results as `UNVERIFIED_MATCH`.
- Require corroborating identifiers before identity-sensitive conclusions.
- Preserve source file, dataset, jurisdiction, retrieval time, matched terms, and hashes when available.
- Keep analyst assessments separate from factual source records.
- Require human review before consequential actions based on investigative matches.

## Data minimization

Screening CSVs contain only search values needed by Horizons. NXYZ-specific metadata such as internal seed IDs, entity type labels, and analyst notes remains in the companion manifest rather than being inserted as search terms.

## Hash semantics

`sourceHash` is optional SHA-256 metadata for the original exported source file when NXYZ has access to the bytes.

`envelopeHash` is generated by NXYZ from the normalized metadata envelope. It detects changes to the normalization record; it does not independently validate the factual accuracy or authenticity of the upstream data.

## Publication and redistribution

Before publishing or redistributing Horizons-derived material, operators must follow the applicable C4ADS terms, dataset restrictions, attribution requirements, and any publication-approval requirements associated with their account or source datasets.
